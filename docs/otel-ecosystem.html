Ecosystem: Backends, Platforms
& Stack Choices

OTEL is a pipeline, not a storage layer. This section maps the backend landscape — OSS tools, SaaS platforms, and which combinations work at each scale tier.

The Ecosystem at a Glance

Your instrumentation stays the same. The Collector routes telemetry to whichever backends you choose — OSS, SaaS, or both simultaneously.

Stack Recommendations by Scale
SMALL

Single service · Low traffic · Small team

Recommendation

  • SaaS platform — skip self-hosted infrastructure
  • Grafana Cloud or New Relic free tier covers most workloads
  • OTLP direct from SDK, or one simple Collector for batching
  • 100% sampling is fine at low volume

Best choices

  • Cost-conscious → Grafana Cloud free tier
  • Traces-first → Honeycomb (best trace query UX)
  • Simplest setup → New Relic (OTLP native, large free tier)
MEDIUM

Multiple services · Moderate traffic · Growing team

Recommendation

  • Managed SaaS or self-hosted OSS stack
  • Single Collector tier for batching, enrichment, basic routing
  • Grafana + Tempo + Prometheus + Loki if you have ops capacity
  • Grafana Cloud if you want the same UX without the ops

Decision point

  • Data residency needed → self-host
  • Move fast, no ops team → Grafana Cloud or Datadog
  • Analytics-heavy → Honeycomb for trace queries
LARGE

Many services · High traffic · Multiple teams

Recommendation

  • Two-tier Collector: agents per node, gateway for sampling & routing
  • OSS with Thanos/Mimir for durable HA Prometheus
  • Datadog or Dynatrace for AI analysis and enterprise breadth
  • Fan-out: different teams can own different backends

Common patterns

  • Platform team owns Prometheus + Grafana
  • App teams send to Datadog APM for product observability
  • Gateway fans out to both from a single pipeline
  • Honeycomb for high-cardinality debugging alongside the main stack
Fan-Out: One Pipeline, Multiple Backends
service:
  pipelines:
    traces:
      receivers:  [otlp]
      processors: [memory_limiter, batch]
      exporters:  [otlp/tempo, otlp/honeycomb]   # both receive all traces

    metrics:
      receivers:  [otlp]
      processors: [memory_limiter, batch]
      exporters:  [prometheusremotewrite, datadog]   # both receive all metrics

    logs:
      receivers:  [otlp]
      processors: [memory_limiter, batch]
      exporters:  [loki]
Self-Host vs. SaaS Decision Guide

// Lean towards Self-Host when…

  • Data residency or sovereignty requirements
  • Ops team available to run infrastructure
  • Data volume makes SaaS cost prohibitive
  • Full control over retention and query
  • Existing Kubernetes cluster with spare capacity

// Lean towards SaaS when…

  • Small or no dedicated ops team
  • Need to move fast and get visibility quickly
  • AI/ML-driven analysis required
  • Enterprise compliance (SOC2, HIPAA) needed out of the box
  • Multiple signal types with one vendor relationship
Rule of thumb: Start with SaaS. Migrate to self-hosted OSS when data volume makes SaaS pricing prohibitive and you have the ops team to support it. The Collector makes migration safe — swap the exporter config, not the instrumentation.
