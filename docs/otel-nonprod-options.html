// Non-Production Observability

Cheaper Options for Dev & Staging
While Keeping Datadog in Production

Production stays on Datadog. Lower environments use a self-hosted, zero-cost stack that receives the same OTEL telemetry. Only the OTEL Collector config changes per environment — Rails instrumentation code is identical everywhere.

The Setup
Production

Datadog

Unchanged. APM, SLOs, alerts, on-call, mobile app. Billed per host — one host only.

→
Dev / Staging

Self-hosted (pick one below)

$0 cost. OTEL Collector routes to a different backend. Same Rails instrumentation as production.

Environment Tiers & Requirements
Local Dev

Developer Laptop / Docker

Ephemeral. One developer. Instant startup. Restart = wipe is acceptable.

Traces (debug request waterfalls)
Single Docker container preferred
Zero configuration
Logs + metrics are a bonus
CI / Test

GitHub Actions / CI Runner

Ephemeral. No UI. Traces optional — used only to detect regressions.

No persistent backend needed
OTEL_SDK_DISABLED=true is valid
Or: Jaeger all-in-one in CI service
Traces recorded, rarely reviewed
Staging

Shared EC2 — Always On

Persistent. Shared by QA, devs, product. Should mirror production observability.

All 3 signals (traces + metrics + logs)
Survives container restarts
Dashboards and alerting
Trace-to-log correlation

Recommendation by Environment
Local Dev

Grafana LGTM

Single container. Zero config. All three signals. Real Grafana dashboards. Developers are up and running in under 5 minutes.

Alt: Jaeger All-in-One if traces are the only need and you want the absolute minimum footprint.
Staging

SigNoz

All three signals. Persistent ClickHouse storage. Trace-to-log correlation built-in. Simplest all-in-one option for a shared staging environment. One Docker Compose, one UI.

Alt: Grafana OSS if the team already has Grafana expertise or wants S3 storage for logs and traces.
Production

Datadog — unchanged

APM, SLOs, alerting, incident timeline, mobile app, anomaly detection. Full-featured production observability. Billed for one host only.

Same opentelemetry-ruby gems. OTEL Collector uses the datadog exporter with your DD_API_KEY.
OTEL Collector Routing Per Environment
Local Dev
No Collector needed
# docker-compose.dev.yml — Rails sends OTLP direct to Grafana LGTM
services:
  rails:
    environment:
      OTEL_RESOURCE_ATTRIBUTES: "deployment.environment=development"
      OTEL_EXPORTER_OTLP_ENDPOINT: http://lgtm:4317
  lgtm:
    image: grafana/otel-lgtm:latest
    ports: ["3000:3000", "4317:4317", "4318:4318"]
Staging
OTEL Collector → SigNoz
# otel-collector-config.staging.yaml
receivers:
  otlp:
    protocols:
      grpc: {endpoint: 0.0.0.0:4317}

exporters:
  otlp/signoz:
    endpoint: signoz-otel-collector:4317
    tls: {insecure: true}

service:
  pipelines:
    traces:   {receivers: [otlp], exporters: [otlp/signoz]}
    metrics:  {receivers: [otlp], exporters: [otlp/signoz]}
    logs:     {receivers: [otlp], exporters: [otlp/signoz]}
Production
OTEL Collector → Datadog
# otel-collector-config.production.yaml
receivers:
  otlp:
    protocols:
      grpc: {endpoint: 0.0.0.0:4317}

exporters:
  datadog:
    api:
      site: datadoghq.com
      key:  ${DD_API_KEY}

service:
  pipelines:
    traces:   {receivers: [otlp], exporters: [datadog]}
    metrics:  {receivers: [otlp], exporters: [datadog]}
    logs:     {receivers: [otlp], exporters: [datadog]}
